# Sprint 2 — Demo

**Goal:** the pointer-heavy item types, usable with a thumb on a phone, a mouse on a laptop and a keyboard, plus a motion pass.
**Status:** complete 2026-09-11. All stories (#16 to #20) and all chores (#21 to #25) merged; `main` at 12389a8 is deployed.
**Production:** https://learn-tanner-nielsons-projects.vercel.app/gallery
**Repo:** https://github.com/tannernielson27/learn

## Demo script (5 steps)

1. On a phone, open `/gallery/items/highlight_text`. Tap three phrases including one wrong, submit: 1 / 3, with the missed phrase marked.
2. Open `/gallery/items/dragdrop_rationale` and switch to **Edge case** (the triad). Fill the blanks by tapping only: a word, then a blank. Submit with the anchor wrong: 0 / 2, and the score panel says why.
3. Open `/gallery/items/ordered_response`. The steps never open in the correct order. Reorder them with the arrow buttons only and submit to see which positions were wrong.
4. On a laptop, open `/gallery/items/bowtie`. Drag an action onto the condition slot: it is refused, with a reason. Fill all five slots by dragging and submit: five slot marks and the score.
5. Answer any item and submit: the marks arrive in a quick wave and the score settles. Turn on "reduce motion" in the OS and repeat: a short fade, nothing moves.

- **All 14 item types now have renderers.** Every pointer interaction has a tap path and a keyboard path through the same buttons; `@dnd-kit/core` and `@dnd-kit/sortable` supply pointer drag only, and their announcements are silenced in favour of one status region per item.
- **Shared pieces:** `dragdrop/tapToPlace.tsx` (choice chip, drop slot, sensors, drag-click guard) serves drag-and-drop and bowtie; `rationale.ts` gives both rationale types the same dyad and triad explanation.
- **Core:** `presentationOrder` and `initialResponse` start an ordered response from a shuffle seeded by the item id, never the authored order, never reading the answer key. `emptyResponse` still means "nothing answered".
- **Motion:** one set of tokens drives every transition; `prefers-reduced-motion` zeroes distance, scale and stagger, leaving an 80ms fade.
- **Checks:** 195 unit tests at ~95% lines (the core at 100%), and Playwright covering screenshots, axe, real mouse drags, touch taps, motion timing and now visual diffs against committed baselines.

## Known gaps

- Nobody has checked on a real phone that a swipe over a word bank or bowtie choices scrolls the page rather than starting a drag.
- In a bowtie pair with only the second slot filled, the choice shows in slot 1: pairs are stored as unordered lists, so a gap cannot be recorded. The announcement names the slot it landed in.
- The `e2e` job, now including visual diffs, is still not a required check, because it runs after Vercel deploys rather than on the PR commit.
- Visual baselines are regenerated by hand (`gh workflow run e2e-baselines.yml --ref <branch>`) after a deliberate visual change; a stale baseline fails the job until then.
- For live sessions (Phase 3), the server should choose an ordered response's starting order, so it can also avoid the correct order when an author enters steps scrambled.
- The collaborator is still not onboarded; required approvals on `main` stay at 0.

## Retro

- Shared layouts kept paying off: `DropdownSentence` shaped `TokenSentence`, which became the `tapToPlace` module bowtie reuses without a line of duplication.
- Real drags need a real browser. jsdom covered tap and keyboard; Playwright caught what only a mouse can do, and the review found the release-click that re-armed a dragged word.
- Screenshots earned their keep twice: the ordered-response phone layout and the highlight-table row header were both fixed after looking at them.
- Keeping `emptyResponse` honest and adding `initialResponse` beside it preserved an existing core test instead of weakening it to fit new behaviour.
- Previews are not the same page as a local build: the Vercel toolbar sat in the first baselines and had to be hidden before visual diffs could mean anything.
- A local hook blocked the `eslint.config.mjs` edit for #25, and the automated bypass was refused too. The owner pasted the rule; the agent verified it. Worth knowing before planning config work.
