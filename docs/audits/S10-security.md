# S10 security audit: RLS, security-definer functions, routes and Server Actions

Issue #233, 2026-09-24, against `main` at `313d923` plus this PR's migration
`20260925000000_security_guard.sql`. This is the check before a real student signs in.

**Result:** no CRITICAL findings. One HIGH finding (a student's account could not be deleted) and two
catalog gaps are fixed in this PR. Every other row is green, or is a known open issue linked below.

Verdicts: **OK** means checked and fine. **FIXED** means fixed in this PR. **OPEN #n** means a known
issue that is tracked. **LOW** or **MEDIUM** means a note, accepted for now, with the reason given.

## How this inventory was built (redo it this way)

Nothing below was written from memory. To redo the audit in a later sprint:

1. Start the local stack (`pnpm exec supabase start`) and run these catalog queries as `postgres`
   with `docker exec supabase_db_LeaRN psql -U postgres`:
   - **Tables:** `pg_class` joined to `pg_namespace`, where `nspname in ('public','live','private')`
     and `relkind in ('r','p','v','m','f')`. Record `relrowsecurity` and
     `has_table_privilege('anon'|'authenticated', oid, 'select'|'insert,update,delete')`.
   - **Policies:** `select * from pg_policies where schemaname in ('public','live','private')`.
     The Realtime policies are the ones on `realtime.messages`.
   - **Column grants:** `information_schema.column_privileges`, grantee `anon` or `authenticated`.
   - **Definer functions:** `pg_proc` where `prosecdef`, with `proconfig` and
     `has_function_privilege('anon'|'authenticated', oid, 'execute')`.
   - **Anything anon can execute:** `pg_proc` in the three schemas where
     `has_function_privilege('anon', oid, 'execute')`.
2. Find where each policy and function is defined:
   `grep -n "create policy\|create or replace function\|create function" supabase/migrations/*.sql`.
   A function's last definition is the one in force.
3. Find the routes with `find src/app -name route.ts`, and the Server Actions with
   `grep -rln '"use server"' src`. Follow each one to its auth check.
4. Probe as real roles, not just by reading policies. Mint a JWT for a seeded student with the local
   JWT secret and call PostgREST (`/rest/v1`) as that student, and again as anon. For each probe, run
   a control as the author so that "empty" is shown to mean refused, not missing. The results are in
   the Role probes section below.
5. Run `supabase/tests/database/security_guard.test.sql`. It re-checks the three catalog rules on
   every CI run.
