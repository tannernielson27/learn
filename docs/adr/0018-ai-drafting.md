# ADR 0018 — AI drafting behind teacher review: a suggested rationale and a variant, never published by the AI

- **Status:** Proposed, 2026-11-25 (owner decision). Narrows ADR 0008's "Extract only" to AI import, which does not change. The terms and privacy wording below is proposed and awaits the owner's approval.
- **Deciders:** product owner (the four decisions below), Claude (planner)

## Context

ADR 0008 built AI import on one rule: "The model copies; it never invents." That rule is in the ADR, in the two import prompts (`src/lib/aiImport/extract.ts`, `segment.ts`), in code comments, on the teacher guide and in the terms. It was right for import: a key or a rationale the model makes up and a teacher misses would reach students as if the teacher wrote it.

Teachers still have to write what import cannot copy. A 2022 national survey found half of nurse educators not confident writing NCLEX-style questions, and every source names time as the barrier. The slowest parts are a rationale for each option and a second version of a question for practice or a retake.

The limits come from the same sources. Studies of AI-written cases and questions found the quality uneven: some items were sound, some had a wrong or arguable key, some rationales explained an answer the item did not key. So whatever the AI writes is a draft for a teacher, never something a student sees on its own.

On 2026-11-25 the owner chose to let the AI draft in two narrow places, behind the teacher's review. This ADR is the one record of what that allows, what it does not, and every sentence in the product that has to change. The build issues are #621 (one Claude call path and one monthly cap), #622 (suggest a rationale), #623 (write a variant) and #624 (an eval before the flag goes on). #625 (a whole case study) is parked.

## Decision

### Owner decisions, 2026-11-25

1. **The AI may draft a rationale for a question the teacher has already keyed.** It explains the key the teacher set. It never explains a different answer.
2. **The AI may draft a variant of an existing question:** a new question of the same type, testing the same thing, with its own key and rationale.
3. **Drafting a whole case study is parked** (#625).
4. **AI import itself does not change.** It still copies and never writes a key or a rationale. The import prompts stay as they are.

### Rules every drafting feature follows

1. **Nothing the AI writes is saved or published without the teacher's own action.**
   - A suggested rationale enters the form only when the teacher presses Use (or Use all), and is saved only by the teacher's Save. Dismiss, leaving the page or a refusal leaves the form as it was.
   - A variant is created only by the teacher's own press of Write a variant. It is created as an unpublished draft question in the same quiz, which no student path can reach (rule 6). It holds the AI's question, key and rationale, all marked as drafted.
   - Nothing is published except by the teacher's own Publish. No drafting path publishes, assigns, shares or starts anything.
2. **The AI never changes an answer key a teacher set.** A rationale suggestion is offered only for a complete, valid key, explains that key as given, and fills empty fields only. If the model cannot explain the key, it returns a note to the teacher and no rationale. A variant writes its key on the new question; the question it was written from is never touched.
3. **Where the AI writes a key, the question cannot be published until the teacher confirms it.** A variant is marked Answer key not confirmed until the teacher presses Confirm answer key on the question page. Confirming is a deliberate action, never a side effect of opening, editing or saving. The check is in `publishBlockers` and in `checkPublishable` on the server, so no path around the editor publishes it. Once confirmed, the key is the teacher's, and rule 2 applies to it.
4. **The teacher can always see what the AI drafted.** A suggestion is shown in full beside its field before the teacher chooses. Text the teacher keeps is marked Drafted with AI on the question and in its version history, and the mark stays when the teacher edits the text. A variant records which question it was written from, and one that repeats too much of the original's stem is flagged Very close to the original.
5. **A student never sees a mark that says so, and never sees a draft.** The marks are author-only. Student routes serve published questions only, through the same server-side projection as today (ADR 0003), so neither a variant before Publish nor a suggestion the teacher did not keep can reach a student.
6. **The server holds the key, not the client** (ADR 0003). A drafting request is a Server Action on an author route. The server reads the question, its key and its rationale from the database for a teacher who may edit it, and checks the model's answer there. Scoring does not change.
7. **What is sent to Anthropic:** the question's own text, key and rationale, and for a case study step its patient record as it stands at that step (`recordAtStep`), no further. Never a student's name, answer or result, and nothing that identifies the teacher.
8. **Question text is data,** as document text is in ADR 0008. It is wrapped in the same `<document>` element and escaped the same way (`escapeDocument`, made shared by #621). An instruction inside it is ignored. The model has no tools that act on anything.
9. **The model's answer is checked before the teacher sees it.** It must pass a Zod schema; every option, row or blank id it names must exist on the question; a variant goes through the loose per-type draft shape AI import uses and the converters in `src/lib/ngn/draft/`, then `itemSchema`, with one repair attempt, else nothing is created. Everything is rendered as text through the existing components, never as HTML.
10. **Requests and answers are scrubbed from Sentry** like answer keys and document text (`src/lib/observability/scrub.ts`).

### Decisions for the build issues to follow

Each is to be confirmed in the issue that builds it.

1. **One monthly cap per workspace covers import and drafting together:** `orgs.ai_import_monthly_cap_usd`, default 10.00. `public.ai_usage` stays one row per workspace and month. A reservation records its `kind` (`import` by default, or a drafting kind) on `private.ai_usage_reservations`, through a new `reserve_ai_usage` argument (#621). The code names keep "import"; the interface calls it the workspace's monthly AI allowance.
2. **The workspace switch `orgs.ai_import_enabled` governs both,** and it and the cap are still checked inside `reserve_ai_usage`.
3. **A separate environment flag, `AI_DRAFT_ENABLED`, off by default,** read by `aiDraftEnabled()` beside `aiImportEnabled()`, so drafting can ship dark. With it off, the drafting buttons are not shown. `AI_IMPORT_ENABLED=false` still turns import off; it does not turn drafting on.
4. **The flag goes on in production only after the drafting eval passes its bar** (#624: a nurse educator reviews 20 rationales and 20 variants, and none of the rationales is marked wrong). It may go on in previews and on staging, which hold only test content (ADR 0017), for the eval and the owner's testing.
5. **The limiter** (`public.hit_rate_limit`) has two buckets, `ai_draft_rationale` and `ai_draft_variant`, 30 an hour per teacher each, failing closed.
6. **Refusals leave everything as it was** and say why in one sentence: AI is off for this workspace; This month's AI allowance is used up; Try again in a few minutes.
7. **The marks live in author-only columns on `items`,** not in `items.content` or `answer_key`, so the item contract (ADR 0004) and `learn.v1` do not change and the student projection needs nothing new. If a build issue puts a mark in the item itself, `ITEM_FIELD_VISIBILITY` must classify it as author-only.
8. **A variant starts with the AI's own rationale,** marked Drafted with AI. The teacher's Publish, after Confirm answer key, is what accepts it.
9. **Suggest a rationale is offered on a variant only after its key is confirmed,** because owner decision 1 covers a question the teacher has keyed.
10. **Duplicate keeps both marks.** A copy of an unconfirmed variant is still unconfirmed, and text marked Drafted with AI stays marked.
11. **First slice of variants:** multiple choice, select all that apply, select N, both matrix types and the three drop-down types, for standalone questions only. Every other type says Not available for this type yet.
12. **The fake Claude client** answers drafting requests in tests and refuses to run in production (#621).

## Consequences

- **"Extract only" now means import.** ADR 0008 says so and points here. A comment or prompt that says "the AI never writes a key" stays true of import; a drafting module says which rule it follows by citing this ADR.
- **One allowance, two uses.** A teacher who drafts a lot leaves less for import that month, and the upload page's "about N documents left" counts both. The default of $10 stays until real use says otherwise.
- **Drafting can ship dark.** #622 and #623 can merge with `AI_DRAFT_ENABLED` off in production; the wording rows above ship with the code, so the guide, terms and privacy describe drafting from the day the code is on `main`. The terms and privacy rows need the owner's approval before that PR merges.
- **No migration here.** #621 adds the reservation `kind`; #623 adds the variant's columns on `items`.
- **A new evaluation.** `test/ai-import/` measures copying. Drafting needs a reviewer's judgment, so #624 records a nurse educator's verdicts, and a prompt change for drafting reruns it before the flag stays on.

## Risks accepted

- **A plausible but wrong rationale.** The model explains the teacher's key, and a teacher may press Use without reading closely. The mark, the eval bar and the teacher's own Publish are the defence; the terms say the teacher is responsible for what they publish.
- **A key the teacher confirms without checking.** Confirm answer key is one deliberate press, not a review the product can verify.
- **The marks do not travel in `learn.v1`.** An exported variant imported again as JSON arrives as the teacher's own question, with no mark and no unconfirmed key. That is the teacher's own file, deliberately re-imported.
